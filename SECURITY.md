# Security policy

## Supported versions

Security fixes are prepared for the current version on the `main` branch.

## Reporting a vulnerability

Do not publish a vulnerability as a regular issue. Use
**Security → Report a vulnerability** in the GitHub repository. If private
reporting is unavailable, email [git@vms.net.pl](mailto:git@vms.net.pl).

Include:

- application version and operating system;
- the smallest reproducible scenario;
- the expected impact;
- whether the issue needs a specially crafted file or script.

Do not attach private media, metadata, local paths, or secrets. If a file is
needed, create a minimal test file with no personal data.

The author will acknowledge the report, assess the impact, and coordinate a
fix. Timing depends on the complexity and availability of a safe solution.
